## v0.1.2 验证（2026-10-14）

- Go 全部测试、go vet、Vue TypeScript 和 Vite 构建通过。
- 新增测试覆盖订阅 DNS 继承、覆写持久化和隔离、非法上游拒绝、失败回滚、revision 与订阅绑定冲突；同时修改 DNS 与启用 TUN 时，超时恢复也恢复原 DNS。
- 加密备份测试覆盖明文不泄漏、错误密码和篡改拒绝、HTTP 认证及恢复保留管理身份、端口和关闭 TUN。
- 内核维护操作只允许固定路径，配置和日志凭证脱敏通过测试。
- Playwright 9 项测试通过，新增 DNS 预设保存、深色主题、启动页面偏好、备份验证焦点、实时连接筛选和关闭确认、失败数据保留、日志暂停和清空。390px 手机布局及 axe 检查无违规。
- frontend premium strict 审计无错误；DESIGN.md lint 无错误，既有语义 token 文档引用提示保留。

GPUserver1 故障隔离：生产配置中 TUN 强制使用的 Cloudflare / Google DoH 从本机无法直连，同一 AnyTLS 节点在独立临时内核中旧 DNS 延迟测试失败，切换国内 DoH 后成功 331 ms，生产内核 PID 未变。订阅本身已有国内 DNS，被旧生成器覆盖。其他服务器可直连旧 DNS。部分 SS / VMess 节点域名在其他服务器也返回 NXDOMAIN，属于另一个订阅节点问题。

GPUserver1 已由管理员执行带备份、校验和 DNS 覆写的部署脚本，安装 v0.1.2 开发版。SSH 恢复后实际复核：管理后台与内核均 active，DNS 返回 rcode 0 / 3 条结果 / 83 ms，当前 HTTP 代理请求 Google generate_204 返回 HTTP 204 / 406 ms。全节点脚本的逐项结果保存于服务器 `/var/backups/meshport/dns-v0.1.2-verification.json`，受 root 权限保护，本次未直接读取该报告，不宣称所有节点可用。GeoData 更新、关闭真实连接和恢复真实备份未在生产环境执行；对应测试使用模拟内核或临时数据。GitHub 构建与发布记录以对应 v0.1.2 Release 为准。

## 真实测试环境

Ubuntu 22.04 LTS、amd64、Linux 5.15、systemd、Mihomo v1.19.32。通过 SSH 与授权的 sudo 权限执行测试。

`scripts/acceptance.py` 验证：

- 首次初始化、后续登录、未登录限制及初始化凭证不可重复使用。
- 节点列表模板和完整配置订阅，统一管理入站、端口与 TUN。
- 真实内核启动、停止、重启；节点选择、模式、代理端口、自启状态持久化。
- 重启管理后台时内核继续运行；SIGKILL 内核后后台仍可登录和操作。
- 无效订阅更新保留原运行配置与缓存；移除原已选节点后清除失效选择并提示。
- 删除运行中的当前订阅被拒绝；停止后可以删除。
- HTTP 代理端口冲突保留原配置；Web 端口冲突保留原监听。
- Web 8888 → 8889 → 8888 迁移正常；新端口先启用，旧端口随后关闭。
- 外部代理无凭证时 HTTP 返回 407；恢复仅本机访问正常。
- TUN 开启时 SSH 与 DNS 可用；等待确认期间后台可访问。
- 停止后台后，独立计时器仍在 60 秒窗口到期后恢复旧设置与代理状态；本工具网卡与路由规则得到清理。
- TUN 显式确认、关闭与后续 DNS 正常。

`scripts/lifecycle-test.py` 验证默认卸载保留管理员密码、订阅、设置与自启选项；重新安装正常。明确 `--purge` 删除本工具数据后重新安装，返回待初始化状态。辅助程序拒绝未知命令和多余参数。
